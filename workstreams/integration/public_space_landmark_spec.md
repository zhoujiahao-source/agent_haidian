# Public Space & Landmark Specification

## Status

Conceptual urban-design specification. Exact sites / dimensions / heritage-control relationships must be tied to verified geometry and sources before formal insertion.

# 1. Public space thesis

AI public space should not look like an AI exhibition.

The spatial thesis is:

**Public Capability Interface｜公共能力接口**

A person should experience **a city that can help**, not a city covered in screens explaining that it uses AI.

# 2. Two-layer interface

## Ambient Layer

Low-risk environmental / collective functions may operate by default when legally and ethically appropriate.

Examples:

- non-personal environmental state display;
- public lighting / shade / environmental support within appropriate controls;
- basic non-personal wayfinding state;
- public event / service status.

Rules:

- no hidden individual profiling;
- public function remains understandable without an app;
- ordinary physical fallback remains available.

## Consent Layer

Personalized or person-related services require active request / appropriate consent.

Examples:

- accessible-route assistance;
- personal service navigation;
- customized recommendation;
- individual assistance / handoff.

Rules:

- minimal data;
- easy refusal;
- refusal must not remove basic public service;
- Human Override / human alternative visible.

# 3. Everyday-life priority

Every node must pass the **AI-Off Test**:

> If the digital / AI layer disappears for a week, is this still a useful, comfortable and legible public place?

Required physical basics remain primary:

- shade / shelter where appropriate;
- seating / rest;
- accessible movement;
- lighting;
- ordinary signage;
- clear entrances / connections;
- public facilities / services where relevant;
- safe coexistence of different users.

# 4. Node family

## Type A — Exchange Commons

Role:

- major Capability Backbone meeting / transfer point;
- city-version / active-scenario overview;
- ordinary daily public space;
- annual learning assembly support where appropriate.

Spatial ingredients:

- generous accessible public realm;
- multiple movement choices;
- visible but non-dominant public information layer;
- flexible event / discussion / demonstration capacity;
- shade / seating / everyday amenities.

## Type B — Neighborhood Service Interface

Role:

- low-friction access to local public capability;
- human service handoff;
- community feedback.

Spatial ingredients:

- small, distributed, familiar scale;
- conventional service information;
- staffed / human fallback where service importance requires it;
- accessible seating / queue / consultation conditions.

## Type C — Climate / Resilience Interface

Role:

- heat refuge / environmental adaptation / emergency support.

Spatial ingredients:

- physical shade / green / water or indoor refuge relationship where evidence supports it;
- clearly visible non-AI refuge function;
- emergency mode not dependent on personalized tech.

## Type D — Mobility / Accessibility Interface

Role:

- station / crossing / route support;
- accessible route status and human assistance.

Spatial ingredients:

- physical route legibility;
- tactile / visual / universal information methods as applicable;
- real crossing / transfer improvement before digital assistance.

## Type E — Experimental Interface

Role:

- reversible real-world pilot.

Spatial ingredients:

- clear temporary boundary;
- visible experiment state / end date / review route;
- safe rollback;
- minimal permanent construction until value demonstrated.

## Type F — Memory / Learning Interface

Role:

- railway memory;
- city-learning records;
- retired capability / version archive.

Spatial ingredients:

- physical artifact / material / route;
- public archive / display;
- source traceability;
- distinction between historical fact, present experiment and future proposal.

# 5. Scenario orchestration by time

Nodes should not all perform all functions continuously.

## 07:00–10:00 Morning Commute

Priority:

- mobility / transfer;
- accessible routes;
- weather / heat state;
- concise public information.

Avoid:

- event clutter;
- excessive interaction steps.

## 10:00–15:00 Civic / Learning / Rest

Priority:

- public services;
- community use;
- research / learning exchange;
- shade / rest;
- cultural interpretation.

## 15:00–18:00 School / Family / Community

Priority:

- child / caregiver routes;
- community public life;
- accessible service;
- low-risk programming.

## 18:00–24:00 Night Culture / Service

Priority:

- cultural route;
- public transport / wayfinding;
- lighting / rest;
- resident-impact management;
- non-surveillance-centered safety support.

## Extreme Heat Mode

Priority:

- refuge network;
- shortest safe / accessible shade route;
- public facility / water / rest information;
- vulnerable-user access.

## Emergency Mode

Priority:

- official human authority;
- verified information;
- accessible refuge / route;
- AI advisory role only where appropriate;
- conventional fallback fully visible.

# 6. Three flagship landmarks

## Landmark 1 — 1909 Railway Memory / 铁路记忆

### Core question

How can the site make the previous technological revolution physically present without becoming a nostalgic theme park?

### Design direction

- preserve / interpret verified railway traces / objects / station memories where available;
- use material / alignment / milestone language;
- show engineering / infrastructure / public-life transformation;
- connect historical innovation to the spatial logic of movement and exchange.

### Avoid

- fake historic reconstruction;
- unsupported heritage geometry;
- decorative locomotives unrelated to actual evidence;
- equating past railway governance directly with AI governance.

### Public program

- railway-history interpretation;
- technical-culture education;
- intergenerational public space;
- start / anchor for the 1909 → 2026 → Future route.

## Landmark 2 — 2026 City Learning Archive / 城市学习档案

### Core question

Can a city make its own experiments, failures and changes visible as public memory?

### Design direction

A walk-in / traversable civic archive integrated into public space rather than a conventional “AI museum”.

Archive content:

- problem records;
- experiment versions;
- public-value metrics;
- STOP / MODIFY / CONTINUE / SCALE decisions;
- citizen / professional review records where public;
- city-version changelog;
- retired-capability stories.

### Physical language

- version layers;
- replaceable panels / modules;
- milestone / switch / track graphic DNA;
- durable archive + adaptable annual layer.

### Key rule

The archive must display failures / stopped projects, not only success.

## Landmark 3 — Future Experimental Station / 未来实验站

### Core question

Can uncertainty itself become a legitimate civic program rather than being hidden behind future-tech spectacle?

### Design direction

A real, governed test facility / public experimental space for unresolved urban questions.

Possible functions:

- modular experiment bays;
- public observation / discussion;
- developer / university test interface;
- controlled-to-public test transition;
- clear state / risk / review information;
- reversible construction / utilities where feasible.

### Key rule

The station does not promise a future answer. It makes the **process of testing** public and governable.

# 7. Retired Capability Archive

Formal name preference:

**城市能力退役档案 / Retired Capability Archive**

Internal provocative term `城市能力墓园` should not dominate public-facing formal material unless intentionally justified.

## What is archived

Important retired:

- AI services;
- robots / devices;
- public-interface prototypes;
- software / agent versions where representable;
- failed experiment artifacts;
- obsolete public-service hardware.

## Required record

1. What problem was it intended to solve?
2. Who was affected?
3. What data / infrastructure did it require?
4. What public value did it create?
5. What failure / limitation emerged?
6. Why was it stopped / replaced?
7. What replaced it or what non-AI fallback remains?
8. What lesson changed future city rules?

## Spatial formats

- physical object storage / display for selected artifacts;
- material “retirement markers” at original nodes where appropriate;
- annual version wall / timeline;
- public searchable archive;
- repair / disassembly / material-reuse narrative for hardware.

# 8. 1909 → 2026 → Future route

The three landmarks should not be isolated objects. They should form a **time route** along / connected to the Capability Backbone.

Narrative:

`1909: technology changes movement and national engineering confidence`

→

`2026: AI enters real public life and must be tested against public value`

→

`Future: technology remains replaceable, while the city's learning / exchange capacity persists`

The route must remain rooted in verifiable Jing-Zhang / Zhongguancun context, not a generic “past-present-future” exhibition trope.

# 9. AI-native business in 大钟寺

Public-space / landmark design should support the official AI-native-business task without turning public space into a showroom.

Recommended spatial model:

- temporary service sandbox spaces;
- public-value / experiment-state tags;
- mixed conventional + AI service access;
- small / medium actor participation opportunities;
- test-to-market / test-to-public-service pathways;
- event / night public-life compatibility;
- public feedback / human service points.

Commercial success alone is insufficient for SCALE.

# 10. Public-space visual information

At a node, the user should be able to read only what they need.

Recommended hierarchy:

## Level 1 — ordinary use

- where am I?
- what public service / route / facility is available?
- is there a non-digital option?

## Level 2 — capability state

- is this an existing service or a test?
- current lifecycle state: TEST / MODIFY / CONTINUE / SCALE / RETIRED as relevant;
- optional deeper explanation.

## Level 3 — governance / evidence

- evidence status;
- risk / consent mode;
- review / feedback route;
- version history.

Do not place dense governance text on every bench / sign.

# 11. Section briefs

## Section A — Backbone Everyday Section

Show:

- conventional pedestrian / cycle / street / green / rail relationship based on real geometry;
- ordinary seating / shade / public facilities;
- one subtle capability interface;
- AI-Off fallback;
- Known / Proposed distinction.

## Section B — Experimental Node Section

Show:

- permanent base public space;
- adaptive utilities / platform;
- temporary experimental layer;
- visible test boundary;
- Human Override / staff / conventional fallback;
- removal / rollback condition.

## Section C — Memory / Future Section

Show:

- historic trace / material;
- city learning archive;
- future experiment bay;
- continuous public route;
- old / current / proposed information layers.

# 12. Rendering / figure rules

Prompts / visual production should emphasize:

- Beijing / Haidian-specific urban reality;
- public-service design;
- ordinary people and mixed ages;
- daylight / real materials;
- railway-derived line / node logic;
- physically plausible public space;
- subtle, secondary technology;
- clear captions explaining evidence vs proposal.

Avoid:

- neon holograms;
- giant robot / brain sculptures;
- blank futuristic plazas;
- screen walls as the primary architecture;
- crowds all holding phones;
- autonomous robots everywhere;
- fake heritage reconstruction;
- impossible infrastructure geometry.
