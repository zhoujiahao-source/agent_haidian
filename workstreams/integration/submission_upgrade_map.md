# Submission Upgrade Map

## Goal

Evolve the existing `jingzhang-legible-ai-belt` submission from an earlier **Legible AI** framing into the current **City OS + Capability Backbone + Urban Capability Exchange Network** framework while preserving any valid evidence, geometry, metrics, figures and compliance work already completed.

This is a migration map, not permission to discard previously validated work.

## Concept hierarchy after migration

### Primary concept — KEEP AS HEADLINE

**城市成为 AI 进入现实世界的操作系统**

The proposal is a city-scale operating system for converting emerging AI capability into tested, governed and transferable public capability.

### Primary spatial idea — KEEP AS SPATIAL HEADLINE

**Capability Backbone｜城市能力交换骨干**

A physical + service + learning urban backbone connecting distributed learning units.

### Primary success criterion — KEEP AS GOVERNANCE HEADLINE

**Public Value｜公共价值**

AI deployment count is not success; measurable improvement in city conditions is.

### Flagship metric — KEEP AS METRIC HEADLINE

**Urban Adaptation Rate｜城市适应率**

### Long-term legacy — KEEP AS END-STATE HEADLINE

**Urban Capability Exchange Network｜城市能力交换网络**

### `Legible AI` — DOWNGRADE FROM MAIN CONCEPT

`Legible AI / 可读 AI` can remain only where useful as a principle of:

- governance transparency
- evidence provenance
- public-facing state / risk / uncertainty labeling
- explanation of who authorized an experiment and why
- visual information design

It must no longer compete with City OS as a second headline concept.

## Legacy elements likely worth retaining

Retain only after checking against latest repo / evidence:

1. Existing source registry and citation work that is still valid.
2. Existing geometry that conforms to current allowed-design-space rules.
3. Existing reproducible planning metrics.
4. Existing five required figures if their base spatial evidence remains valid; redesign content / captions only where needed.
5. Existing compliance, standards and design-depth matrices when IDs / schema are still current.
6. Existing bilingual structure and rendered deliverables where still structurally compatible.
7. Existing public-interest / transparency ideas that can be reinterpreted as `Legibility Layer` rather than main narrative.
8. Existing provisional-boundary disclosures.

## Elements that require conceptual rewrite

### 1. Opening thesis

OLD tendency:

`让 AI 可读、可审计、可治理`

NEW hierarchy:

`让 AI 通过城市操作系统转化为真实公共能力；可读、可审计只是治理层的必要条件。`

### 2. Spatial structure

Any abstract `AI belt` diagram must be upgraded to a specific spatial explanation of:

- what the Capability Backbone physically consists of
- where it stitches east–west and north–south
- how it interacts with rail heritage, roads, parks, communities and innovation resources
- how nodes differ by capability and risk / experiment state

### 3. Three areas + two wings

Replace generic zone descriptions with resource-based capability specialization:

- 众智园 = full-stack capability production / technical validation
- AI 原点社区 = talent / social feedback / public-service learning
- 大钟寺 = market and AI-native urban-service validation
- 中关村科技服务翼 = resource / capital / IP / service exchange
- 小月河场景赋能翼 = real public-space scenario testing

Each zone may have secondary capabilities but must remain differentiated.

### 4. AI governance

Replace any one-way `deploy → monitor` logic with:

`diagnose → authorize by risk → reversible real-world test → public-value review → STOP/MODIFY/CONTINUE/SCALE → transfer with revalidation`

### 5. Metrics

Retain statutory / conventional planning metrics required by schema, but add a distinct city-learning metric family.

Urban Adaptation Rate must be a proposed reproducible definition, with no invented observed value if baseline data do not exist.

### 6. Public space

Replace visible-AI spectacle with:

**Public Capability Interface**

- Ambient Layer
- Consent Layer
- Human Override
- all-day mixed public life
- Node Network + Scenario Orchestration

### 7. Landmarks

Replace generic AI iconography with:

**Landmark as Memory**

`1909 railway memory → 2026 city-learning archive → Future experimental station`

and integrate Retired Capability Archive.

### 8. Visual identity

Move from general tech / evidence aesthetics toward **Public Service Aesthetic** using railway double-track, station, switch and milestone DNA.

Logo direction: **Open Node**.

### 9. Long-term operation

Replace generic event / developer-community language with:

- Public Stewardship
- Problem Track + Capability Track
- continuous test / review
- Jing-Zhang City Learning Assembly
- Annual City Version Release
- Retired Capability Archive
- 5 / 10 / 20-year Urban Capability Exchange Network evolution

## Evidence-protection rule

A concept upgrade must never silently upgrade evidence quality.

Examples:

- A provisional boundary remains provisional even if a new masterplan diagram looks precise.
- A derived building-height proxy remains derived.
- A proposed public capability node remains proposed.
- A design scenario is not evidence that a government program exists.
- A suggested public institution is not an actual committed operator.

14. **5 / 10 / 20 Years** — Urban Capability Exchange Network.

> 京张把 AI 转化为公共能力的过程做成一套城市操作系统；三区两翼持续生产与测试能力，Capability Backbone 让能力交换和再验证，公共价值决定 AI 是停止、修改、继续还是扩散，城市通过年度版本发布持续进化。
