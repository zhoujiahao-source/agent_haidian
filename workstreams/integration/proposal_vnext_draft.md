# 0. One-line proposition

**京张不是一座“装上 AI”的城市，而是一套让城市不断产生、交换、检验、升级和淘汰公共能力的城市操作系统。**

The proposal turns the Jing-Zhang corridor into an urban operating system that converts emerging AI capability into **tested public capability** through spatial learning units, a Capability Backbone, risk-tiered authorization, measurable public-value review and long-term versioning.

# 1. Why Jing-Zhang

京张的独特性，不在于“这里适合再做一个 AI 园区”，而在于它同时承载三类能够被组织成一个长期城市命题的资源：

第一，京张铁路代表一轮真实改变城市、区域联系与技术文化的基础设施革命。它提供的不是一个怀旧符号，而是一条关于技术如何进入现实世界、如何获得社会信任、如何改变日常生活的历史线索。最终正式文本必须以当前可验证的官方 / 权威铁路史资料支持相关具体事实，而不依赖概念类比。

第二，海淀 / 中关村具有高校、科研、企业、人才、技术服务和创新资源的现实基础。正式提交应从公开来源建立可追溯的创新生态图，而不是用“创新高地”口号代替证据。

第三，京张沿线并不是一个清空后重新规划的新城。铁路、道路、社区、公园、商业、科研与公共服务交织在真实城市中。这种复杂性恰好使它适合回答一个比“AI 产业集聚”更重要的问题：

> **AI 进入真实社会之后，一座城市怎样判断它是否真的值得留下？**

因此，本方案把赛事固定的三条定位——百年京张文化带、都市 AI 生活体验带、AI 融合创新带——整合成同一个空间 / 治理闭环：历史提供技术文明记忆，日常生活提供真实公共问题，创新体系提供可验证的新能力，而公共价值决定这些能力是停止、修改、继续还是扩散。

# 2. The problem: AI deployment is not urban progress

传统“智慧城市”叙事经常把传感器、平台、模型、屏幕和自动化数量视为进步。但部署量无法回答几个基本问题：

- 普通人是否真的获得更好的公共服务？
- 没有智能手机、拒绝被识别、需要人工服务的人是否被排除？
- 一个在实验室表现优秀的系统，在真实街区是否仍然安全、公平、可维护？
- AI 服务失败时，谁能立即接管？
- 一个项目停止，是失败，还是城市成功避免了更大的错误？
- 一项在众智园验证的能力，是否可以不经重新测试直接复制到小月河或大钟寺？
- 十年后技术淘汰，城市留下的是电子垃圾，还是新的制度与空间能力？

本方案因此拒绝“技术 = 城市进步”的直接等式。

AI 只有经过真实公共需求、风险授权、可逆试验、公共价值评审和跨区再验证，才能成为城市能力。

# 3. Core concept: City OS

“城市操作系统”不是把城市比喻成一台电脑，也不是建设一个控制整座城市的超级平台。

它是一套把 **问题、权力、试验、空间、指标、能力交换和城市记忆** 连接起来的公共机制。

完整学习链为：

`真实问题 → City Agent / 人类诊断 → 资格判断 → 风险分级 → 可逆真实测试 → 公共价值评审 → STOP / MODIFY / CONTINUE / SCALE → 能力登记 → Capability Backbone 交换 → 跨区域再验证 → 年度城市版本发布 → 退役 / 替换 / 归档 → 下一轮学习`

城市由此获得最重要的新公共能力：

**持续学习。**

# 4. Spatial structure: Capability Backbone + distributed learning units

总体结构不是“一个 AI 中心带动全线”，而是：

**一条城市能力交换骨干 + 三区两翼差异化学习单元。**

Capability Backbone 不是一条发光的概念线。它是五种城市基础设施的叠合：

1. **Memory Continuity** — 京张铁路与技术文化的时间连续性；
2. **Public-Realm Continuity** — 能在 AI 关闭后仍然成立的步行、骑行、公共空间和城市连接；
3. **Capability Interface Network** — 普通人调用公共能力的节点网络；
4. **Experiment & Learning Network** — 可逆测试、状态公开和城市学习记录；
5. **Institutional / Capability Exchange** — 研究、人才、资本、IP、服务、市场、社区和真实场景之间的能力迁移。

这五层共同定义“能力骨干”。任何最终总平面都必须说明这五层分别落在哪里，而不能只画一个颜色醒目的轴线。

# 5. Three areas + two wings: five different learners

## 5.1 众智园：从“技术园区”到 Capability Foundry

主能力：**技术验证 / 全栈能力生产。**

这里对应赛事要求中的 AI 全栈自主创新体系，并承担从技术原型到城市测试之前的关键验证：技术性能、失败模式、数据要求、回滚能力、Human Override 和公共需求匹配。

它不应成为封闭的技术岛。真正的价值在于：从这里产生的能力必须能够进入大钟寺、小月河、AI 原点社区等真实环境继续验证。

## 5.2 北京 AI 原点社区：Civic Learning Community

主能力：**社会反馈 / 人才社区 / 公共服务学习。**

世界级 AI 生态不应只由企业与实验室数量定义。这里把人才、研究与社区生活放在同一城市环境中，重点验证 AI 是否让公共服务更容易使用，是否保留人工服务，是否对老年人、残障人士和数字使用能力较弱的人同样有效。

## 5.3 大钟寺：AI-Native Urban Service & Market Test District

主能力：**市场验证 / AI-native 城市服务。**

本方案不把“AI 原生商业”理解成更多自动售卖机、机器人或数字屏幕，而把大钟寺定义为一个受治理的城市服务沙盒：任何新服务都必须证明真实需求、公共空间兼容性、非 AI fallback 和公共价值，才可能从短期测试进入长期运营。

## 5.4 中关村科技服务翼：Innovation Resource Exchange Wing

主能力：**创新资源、资本、知识产权和专业服务交换。**

它使三区两翼不是五个孤立场地：一个城市能力从原型到验证、从验证到市场 / 公共服务、从本地到跨区域迁移，需要法律、IP、资本、专业服务、国际交流和知识网络的支持。

## 5.5 小月河场景赋能翼：Living Urban Test Wing

主能力：**真实公共空间与城市场景测试。**

这里优先回答高温、无障碍、儿童 / 老年公共生活、夜间活动、社区服务、应急模式等真实公共问题。AI 不成为景观主角，而退到 Public Capability Interface 后台。

五个学习单元没有唯一发动机。真实问题可以从任何区域发生，能力也可以从任何区域产生；Capability Backbone 的作用是让经过验证的能力被交换，而不是建立新的中心等级。

# 6. How the city learns: authority before automation

City Agent 可以利用合法、公开、最小必要的数据辅助发现热环境、无障碍断点、服务错配、交通可靠性等问题。但本方案明确：

**AI 可以发现问题，不自动拥有改变城市的权力。**

首先经过 `QUALIFY`：

- 这个问题是否有足够证据？
- 是否有更简单的非 AI 方法？
- 所需数据是否合理？
- 是否影响弱势群体？
- 是否可以回滚？
- 是否能建立 baseline？

只有通过资格判断，才进入风险分级。

低风险场景可以进行小规模、可逆试验；中风险需要更严格专业审批、明确 consent 与 Human Override；高风险场景必须服从更严格的法律、专业与公共责任要求，概念方案本身不构成授权。

所有真实测试都有明确的空间、时间、用户范围、数据范围、停止条件和回滚方式。

# 7. Public Value Review

每个成熟试验最终必须进入四种决策之一：

**STOP / MODIFY / CONTINUE / SCALE。**

其中 STOP 不是必须隐藏的失败。如果试验发现不安全、不公平、隐私成本过高、维护成本失衡或非 AI 方法更好，并在扩大之前及时停止，这是一种重要城市学习。

公共价值评审采用：

**统一底线 + 场景自定义指标。**

统一底线：

- Safety
- Equity
- Privacy
- Environment
- Cost

每个场景另外增加 2–4 个直接指标。

评审不得只看平均值，还必须查看弱势群体、最差情况、空间分布、时间分布、投诉、Human Override、失败与副作用。

# 8. Urban Adaptation Rate

本方案提出旗舰指标：

**Urban Adaptation Rate｜城市适应率。**

它不问“装了多少 AI”，而问：

> 在进入合格城市学习周期的问题中，有多少最终产生了可验证的公共价值改善，或者通过及时停止 / 失败学习减少了未来风险？

工作公式：

`UAR_t = (N_improved + w_stop × N_safe_stop + w_learning × N_verified_learning) / N_matured_cases × 100%`

具体权重必须由未来治理机制透明决定。本竞赛包不得在没有真实历史实验数据时编造一个当前 UAR 数值，因此正式 metrics 中应把它作为“可复现的未来监测框架”，当前值保持 Unknown，除非发现兼容的真实数据。

# 9. Public Capability Interface

AI 公共空间不应该让人先看到 AI。

它首先是一个正常、舒适、无障碍、有遮阴、有座椅、有普通标识、有真实公共服务的城市空间；在此基础上，城市能力通过节点被调用。

本方案采用两层界面：

**Ambient Layer**：低风险、非个人化、环境性的公共能力可以默认运行；

**Consent Layer**：涉及个人数据、识别、推荐、个性化服务时，必须主动调用或适当同意。

所有重要服务保留 **Human Override / AI-Off fallback**。

节点不追求“全能智慧空间”，而形成 Exchange Commons、Neighborhood Service Interface、Climate / Resilience Interface、Mobility / Accessibility Interface、Experimental Interface、Memory / Learning Interface 等不同类型，并根据早高峰、午间、儿童周末、夜间文化、高温和应急状态进行场景编排。

# 10. Twelve scenario portfolio

本方案已经形成 12 个工作场景，正式版本将根据真实数据进一步筛选 / 定位：

1. 高温避暑能力网络
2. 无障碍路径协同
3. 老年公共服务转接
4. 早高峰换乘协同
5. 儿童友好周末模式
6. 夜间文化线路
7. 公共空间应急模式
8. 京张铁路文化解释
9. 公共设施供需协同
10. 大钟寺 AI 原生服务沙盒
11. 众智园全栈能力验证
12. 城市版本公共复盘

其中至少 S01、S10、S11 构成明确的产业 / 技术 / 真实场景测试验证链：

`众智园技术验证 → 大钟寺服务 / 市场验证 → 小月河真实公共场景验证`

它们不是单向流水线；任何阶段都可以触发 STOP / MODIFY，并把问题反馈回能力生产环节。

# 11. People before systems

方案以 8 类设计 archetypes 检验城市是否真正包容：

- 通勤研究员
- 社区老年居民
- 轮椅使用者
- 带儿童照护者
- 大钟寺小型服务经营者
- 众智园青年开发者
- 一线公共服务人员
- 京张文化访客

这些人物不是插画装饰。每一个都会改变空间或治理决策。例如：轮椅使用者迫使“东西缝合”必须成为真实无障碍路线而不是总平面上的连线；老年居民迫使公共服务保留非数字入口；一线工作人员迫使 Human Override 成为实际工作流；小型经营者迫使 AI-native business 避免平台锁定。

# 12. Global ecosystem lessons

本方案选择六个全球研究对象作为可迁移机制，而不是风格模仿：

- Toronto / Vector Institute
- Montréal / Mila
- Singapore / one-north + AI Singapore
- Paris-Saclay
- Boston / Kendall Square–MIT
- London Knowledge Quarter / King's Cross

正式 submission 必须用当前公开来源逐条核实，并避免无来源的比较数字。

六个案例共同提出六个本地问题：

1. 能力在哪里产生？
2. 人才在哪里学习、生活和交换？
3. 原型在哪里被安全验证？
4. 能力在哪里遇到真实市场 / 公共服务需求？
5. 资本、IP、专业服务和治理在哪里进入？
6. 结果在哪里被公开评审、停止、扩散或退役？

京张的差异化答案是：**这些功能不集中在一个 AI Campus，而通过 Capability Backbone 形成分布式城市学习网络。**

# 13. Landmark as Memory: 1909 → 2026 → Future

传统科技地标强调“未来有多先进”。京张更需要表现一座城市如何记住技术。

## 1909 Railway Memory

把经核实的京张铁路历史、遗存 / 场所线索和技术文化转化为可进入的公共空间记忆，而不是复制复古符号。

## 2026 City Learning Archive

保存城市试验的真实版本、公共价值、失败、修改和停止。城市不仅纪念成功，也保存“为什么某项技术不再值得保留”。

## Future Experimental Station

把尚未得到答案的城市问题作为真实公共研究程序。它不是预测未来，而是展示怎样负责任地面对未知。

三者构成一条 **Memory as Place** 的时间路线。

# 14. Retired Capability Archive

城市需要学会“退役”智能系统。

重要退役能力应记录：

- 为什么被创造；
- 解决过什么；
- 产生过什么公共价值；
- 哪里失败 / 过时；
- 为什么退出；
- 被什么替代；
- 对未来规则产生什么影响。

正式公共名称建议使用“城市能力退役档案 / Retired Capability Archive”，避免把失败做成猎奇化的“AI 墓园”。

# 15. Public Service Aesthetic

视觉系统来自京张铁路，但不做怀旧铁路风。

四个母题：

- 双轨 → 并行信息 / 双层界面
- 站点 → 公共能力节点
- 道岔 → STOP / MODIFY / CONTINUE / SCALE
- 里程标 → 1909 / 2026 / Future 与年度版本

Logo 核心是 **Open Node｜开放节点**：一个既像站点、接口、枢纽，又保持开放和交换的公共标识。

整套视觉应更像公共交通与公共服务信息系统，而不是科技发布会。

数据必须区分：Official / Verified / Derived / Assumed / Unknown。

图纸必须区分：Known / Estimated / Proposed / Unknown。

这就是早期“Legible AI”最有价值的保留位置：不是主概念，而是城市操作系统的 **Legibility Layer**。

# 16. Public Stewardship

长期运营采用：

**公共机构主导、社会参与。**

公共责任主体负责安全底线、数据治理、风险授权、公共价值审查与最终责任；高校、科研机构、企业、开发者、社区和市民参与发现问题、提出能力、开发、试验和反馈。

能力通过双入口进入：

**Problem Track**：城市发现问题 → 发布挑战 → 社会解决；

**Capability Track**：社会提出能力 → 必须证明真实公共需求 → 进入测试。

这样既允许底层创新，又避免“企业有技术、城市替它找场景”。

# 17. Jing-Zhang City Learning Assembly

城市全年持续学习，每年形成一次公开结算：

**京张城市学习大会 / Jing-Zhang City Learning Assembly。**

核心仪式不是论坛，而是：

**Annual City Version Release｜年度城市版本发布。**

未来可以以 `Jing-Zhang City v2027` 等形式公开：

- Added
- Modified
- Continued
- Scaled
- Stopped
- Retired
- Unresolved

这里的年份 / 版本是概念运营机制，不表示政府已经承诺在某一年实施。

# 18. 5 / 10 / 20 years

## 5 years

建立可信 basemap、有限真实试验、Capability Registry、公共能力接口原型和第一代城市版本制度。

## 10 years

让多个学习单元能够真正进行跨区能力再验证，强化长期公共空间 / 无障碍 /慢行骨干，形成独立审查与城市学习档案。

## 20 years

今天的大模型和机器人可能已经过时，但京张仍然留下：

**Urban Capability Exchange Network｜城市能力交换网络。**

任何新技术，只要能够证明公共价值，都可以通过同样的风险、试验、评审、迁移和退役机制进入城市。

因此方案真正要建设的不是某一代 AI 基础设施，而是一座城市长期吸收新技术、同时保持公共责任的能力。

# 19. Evidence and uncertainty as design material

第一优先级不是让图纸看起来“完整”，而是把真实场地画准。

数据采用多源交叉验证。官方公开资料、OSM、合法公开影像 / 遥感、公开研究等根据具体问题承担不同角色；冲突必须记录，不能静默覆盖。

允许可信代理，但必须记录来源、日期、方法、许可 / 使用条件、置信度和限制。

如果正式边界、控制指标、产权、道路红线、建筑高度或文保控制线没有足够来源：

**保持 Unknown。**

Unknown 不是失败，而是专业诚实。

# 20. Implementation logic: permanent city, replaceable technology

空间分三层：

**Permanent Infrastructure**：AI 关闭后仍然有价值的公共空间、无障碍连接、绿色 / 遮阴、真实公共服务、文化记忆与开放接口基础；

**Adaptive Layer**：能够随时间调整的公共活动、服务和设施层；

**Experimental Layer**：明确有边界、有结束日期、可回滚的技术 / 服务测试。

这让城市避免被某一代技术锁定。

# 21. What the proposal ultimately claims

本方案不声称一个城市 Agent 可以自动治理北京，也不声称比赛概念已经获得审批、投资或实施承诺。

它提出的是一套可被城市设计、专业规划、数据治理、公共空间和长期运营共同深化的框架：

> **让京张成为一条能够不断把新技术转化为公共能力、再把公共能力变成可交换城市知识的百年创新带。**

从 1909 的铁路，到今天的 AI，再到未来尚未命名的技术，真正持续存在的不是机器本身，而是城市学习、交换、判断和记忆的能力。
