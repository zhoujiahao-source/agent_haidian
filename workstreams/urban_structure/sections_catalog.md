# Sections Catalogue — Minimum Drawing Set

The following section briefs are intended for the Final Integration Agent / visual team. They are not surveyed sections. Each must visibly distinguish `Known / Estimated / Proposed / Unknown` and `Permanent / Adaptive / Experimental`.

## SEC-01 — Railway / East-West Stitch

**Purpose:** prove that “east-west stitching” is a real spatial problem/solution rather than a diagram arrow.

**Show:** verified city fabric and route; railway/barrier relation if known; accessible approach; crossing/passage only if evidence exists; Backbone public interface; active edge; adaptive/experimental elements.

**People:** wheelchair user, commuter, resident, child/older user, maintenance/operator.

**Capability interface:** navigation/accessibility support optional; physical wayfinding and human route remain primary.

**Unknowns to label:** rail protection/control, exact crossing geometry, road redline, ownership, utilities.

## SEC-02 — Xiaoyuehe Blue-Green Public Capability Interface

**Purpose:** show how a public park/water-edge test field remains public/ecological first.

**Show:** verified water/park edge if available; ecological buffer; accessible path; shade/rest; low-sensing refuge; removable low-risk test point; maintenance route.

**People:** walker, older person, child, wheelchair user, maintenance worker.

**Capability interface:** aggregate climate/comfort information or accessibility guidance; no default individual tracking.

**Unknowns:** exact water boundary, hydrology, ecology, flood/maintenance constraints.

## SEC-03 — Zhongzhiyuan Porous Verification Edge

**Purpose:** demonstrate separation and connection between ordinary public life and controlled testing.

**Show:** public path + observation/rest buffer + legible safety edge + controlled test envelope + shared/research frontage.

**Conceptual width cues:** 4–6 m public band; 3–8 m buffer; 6–12 m controlled test envelope where justified.

**Capability interface:** test status, public explanation, human operator, emergency stop.

**Unknowns:** actual building edge, fire access, test equipment, site ownership.

## SEC-04 — AI Origin Learning Neighborhood

**Purpose:** demonstrate a distributed civic interface instead of a standalone AI center.

**Show:** accessible movement; shaded seating/interface band; small civic room; residential/service frontage; optional removable pilot point; analog map/help.

**Conceptual width cues:** 3–5 m movement; 2–4 m interface band; 30–200 sqm civic-room host where feasible.

**Capability interface:** community/navigation/accessibility services with active consent for personalization and visible human help.

## SEC-05 — Dazhongsi Transit-Market Night Interface

**Purpose:** integrate AI-native service testing with ordinary transit, consumption, culture and night use.

**Show:** public movement/waiting; flexible market/event spill-out; service/recovery bay; commercial frontage; night lighting/safety line.

**Conceptual width cues:** 4–6 m public movement; 3–8 m spill-out; 3–6 m prototype/service bay depth at suitable hosts.

**Capability interface:** optional prototype service + human recovery desk; experiments cannot occupy the only public route.

## SEC-06 — Backbone Exchange / Memory Hub

**Purpose:** make Landmark as Memory and City Version Release physical.

**Show:** civic/public room, archive wall/installation, annual release display zone, ordinary seating/plaza, branch wayfinding toward learning units, accessible human help.

**Capability interface:** public capability catalogue/status; no personal data needed for basic use.

**Memory content:** 1909 railway engineering memory → 2026 city-learning archive → future experiment records, including retired/failed capabilities.

## SEC-07 — Permanent / Adaptive / Experimental Overlay

**Purpose:** show one representative location at three time horizons/layers without implying a fixed construction promise.

**Draw three aligned diagrams:**

1. Permanent: access, shade, ecological carrier, civic/human service.
2. Adaptive: market/event/service modules and version display.
3. Experimental: removable pilot boundary/interface with start/end status.

## Drawing QA checklist

Every section should answer:

- What is existing vs proposed vs unknown?
- Who uses the space and at what time?
- What basic public value exists with AI off?
- What is ambient vs consent-based?
- Where is human override/help?
- Which part is permanent, adaptive or experimental?
- Which dimensions are verified and which are only conceptual ranges?
