# Key Area Deepening — Three Distinct Spatial Prototypes

## Status note

All dimensions below are **conceptual section envelopes for design communication**, not surveyed widths, engineering standards, road redlines or approved building controls. They must be replaced or recalibrated using verified site data.

# A. Zhongzhiyuan — Porous Verification Campus

## A1. Spatial structure

Use a three-band relationship rather than a closed science-park perimeter:

1. **Public city edge** — ordinary public route, active frontage, food/rest, developer/public forum and observation points.
2. **Shared verification edge** — review rooms, demo/interpretation, controlled entry, flexible shared halls/courtyards.
3. **Controlled test interior** — pilot-specific safety boundary, test lane/yard or lab interface, human operator and emergency stop.

The public should be able to understand what is being tested without being forced into the test environment.

## A2. Representative section ZZY-01

Conceptual sequence from public realm toward controlled test space:

- 4–6 m clear public movement / social band;
- 3–8 m planted / seating / observation buffer where site allows;
- transparent or legible safety edge;
- 6–12 m pilot-specific controlled test envelope where justified;
- flexible shared hall / research frontage.

These are design ranges only. Final dimensions depend on actual buildings, fire access, testing technology and road/site constraints.

## A3. Node package

- N2 District Learning Node: shared verification commons.
- N4 Experimental Node: controlled test module.
- N5 Memory Node: version/test archive showing STOP/MODIFY as well as successful scale-up.
- N6 Professional Exchange Node connection: standards/IP/legal review from Zhongguancun Wing.

## A4. Public-value tests

- Does the campus edge become more permeable and useful to the city?
- Can the public observe and understand testing without losing safe passage?
- Are risky experiments separated from everyday circulation?
- Does a test have an exit/restoration plan?

# B. Beijing AI Origin Community — Learning Neighborhood

## B1. Spatial structure

Avoid a single “AI community center”. Build a distributed network of daily-life interfaces:

1. **Neighborhood slow route** — accessible, shaded, analog wayfinding.
2. **Small civic rooms** — existing or future-verified ground-floor rooms for human service, community review and capability access.
3. **Courtyard / pocket-space learning nodes** — small gathering and feedback spaces.
4. **Analog refuge / sensor-light spaces** — ordinary quiet public life without mandatory digital interaction.

## B2. Representative section ORIGIN-01

Conceptual street/public-space sequence:

- 3–5 m clear accessible movement band;
- 2–4 m shaded seating / planting / interface band where site allows;
- 30–200 sqm civic/service room or shared ground-floor host where verified feasible;
- active/residential/service frontage;
- optional removable pilot point outside the clear movement route.

## B3. Node package

- N3 Neighborhood Interfaces as the dominant node type.
- N1 Backbone Exchange Hub candidate only if a verified major public host exists.
- N5 `AI Mile Zero` reinterpreted as a public-learning record point, not a technological monument.
- N4 Experimental Nodes only for low-impact/time-limited community services with consent and human alternatives.

## B4. Public-value tests

- Can a person without a smartphone access essential information/help?
- Do older people, children and disabled users have a clear and comfortable route?
- Is personal data use opt-in where required?
- Does the node improve ordinary public life even when no experiment is running?

# C. Dazhongsi — Transit-Market Service Commons

## C1. Spatial structure

Avoid an enclosed “AI mall”. Use the interface between transit, street, commerce, culture and night activity:

1. **Public movement spine** — legible route between transit/daily destinations and the Backbone.
2. **Flexible service frontage** — small bays for service prototypes, repair/recovery and human assistance.
3. **Market / culture spill-out** — reversible public-space programming that works without AI.
4. **Night layer** — lighting, waiting, safe return route and reduced experimental conflict.

## C2. Representative section DZS-01

Conceptual frontage sequence:

- 4–6 m public movement / waiting band where site allows;
- 3–8 m flexible frontage / spill-out band depending on existing condition;
- 3–6 m service/prototype bay depth at suitable hosts, not on the only public path;
- existing commercial/building frontage beyond.

## C3. Node package

- N2 District Learning Node: market/service validation commons.
- N3 Neighborhood/Transit Interface: human service recovery and accessibility help.
- N4 Experimental Node: time-limited service prototype.
- N5 Memory Node: public record of service changes, complaints, failures and replacements.

## C4. Public-value tests

- Does the service reduce friction in a real trip/purchase/service interaction?
- Are workers and small businesses affected fairly?
- Can the public pass through without agreeing to data collection?
- Is there a visible human recovery path when the service fails?

# D. Cross-area differentiation check

| Dimension | Zhongzhiyuan | AI Origin Community | Dazhongsi |
|---|---|---|---|
| dominant urban type | verification campus edge | learning neighborhood | transit-market service commons |
| dominant node | N2 + N4 | N3 | N2 + N3 + N4 |
| dominant risk | controlled technical testing | privacy/inclusion/service access | consent, worker/consumer/service recovery |
| dominant public space | observation + shared test commons | daily streets/courtyards/civic rooms | active frontage + waiting/night space |
| main evidence output | safety/performance limits | public-service/inclusion feedback | usability/demand/recovery evidence |

## Phase 7 conclusion

The three key areas now have different section logic, node packages, users, risks and public-space typologies. The shared City OS language does not make them spatially homogeneous.
