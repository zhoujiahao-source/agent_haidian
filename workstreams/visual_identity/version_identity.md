# Version Identity — Annual City Version Release

Versioning is a public accountability label, not a software joke.

## 1. Canonical visual format

Primary public label:

`JING-ZHANG CITY v2027`

Chinese companion:

`京张城市版本 v2027`

Machine/archival compact token:

`JZC-2027`

## 2. Change types

Every annual release should classify capability changes as:

- `NEW` 新增
- `MOD` 修改
- `EXPAND` 扩大
- `RETIRE` 撤回 / 退役
- `OPEN` 未解决 / 继续公开问题

Do not use green checkmark for NEW and red cross for RETIRE; retirement may be responsible governance.

## 3. Milepost device

Use a compact milepost block:

`V27 · 014`

- `V27`: annual version;
- `014`: capability/release-note index.

The device can appear on node signage, scenario cards, dashboards and archive plaques.

## 4. Release-note visual structure

Each item:

1. version/milepost ID;
2. capability title;
3. change type;
4. area/node;
5. experiment result;
6. risk level;
7. public-value evidence;
8. responsible authority/steward;
9. link/reference to archive or unresolved question.

## 5. Physical-space application

Landmark as Memory should use durable, low-tech-readable inscriptions first. Digital screens/QR may extend the record but should not be the sole memory mechanism.

Suggested plaque hierarchy:

`V2027 / NODE 014`
`Capability: ...`
`Status: MODIFY`
`What changed / why / who reviewed`
`Archive reference`

## 6. Retired Capability Archive

Retirement uses an open-box/archive icon + neutral/dark border. It should read as preserved public learning, not a “graveyard” horror aesthetic.

## Phase 7 checkpoint

Complete: annual version, milepost indexing, release-note and physical archive grammar defined.
