# Layout System

## 1. Shared composition rule

Every output uses the same four zones:

1. **Claim rail** — conclusion title + one-line design claim;
2. **Evidence field** — map/diagram/data visualization;
3. **Annotation rail** — 2–4 numbered callouts and status tags;
4. **Trace rail** — sources, metric IDs, geometry status and version.

This pattern should be visible across A0, A3, HTML, figures, scenario cards and dashboards.

## 2. A0 boards

Recommended 3-board architecture:

### Board A — City OS / Capability Backbone

- overall site story;
- three positionings + five functions;
- three areas/two wings;
- capability exchange logic;
- site-overview + land-use structure.

### Board B — Learning Units / Public Capability Interface

- key areas;
- public space / mobility-bluegreen;
- scenario orchestration;
- Open Node / consent / ambient / override system.

### Board C — Governance / Evidence / Version

- Urban Adaptation Rate and evidence;
- experiment/risk systems;
- annual release / Landmark as Memory / Retired Capability Archive;
- uncertainty and source register.

## 3. A3 booklet

- 8–12 pages recommended;
- each spread has one conclusion + one primary figure;
- detailed source/evidence panels can expand beyond A0 density;
- all status legends repeat only when needed, not as one giant legend page.

## 4. HTML

- sticky compact legend rail optional;
- collapse `Evidence / Proposal / Assumptions / Unknowns` subsections;
- no remote scripts/fonts/iframes/forms/APIs/trackers;
- status filter must have text equivalents; no color-only toggles.

## 5. Scenario card template

Header: scenario ID + title + zone.

Body: public problem → capability → spatial interface → user/persona → human responsibility.

Right rail: `Experiment state`, `Risk`, `Evidence status`, `Design status` as four visibly separate blocks.

Footer: source IDs + version + exit/appeal route where relevant.

## 6. Metrics dashboard

Each metric card includes:

- metric name;
- formula / denominator definition;
- current value or `UNKNOWN`;
- evidence status;
- time coverage;
- distribution/fairness slice where relevant;
- anti-gaming note;
- source/metric ID.

Never show a naked large number without provenance.
