# Iconography

## 1. Construction

All icons use a 24 × 24 grid with 2-unit nominal stroke, round external caps and minimal internal detail. They should match Open Node geometry.

## 2. Core civic icon family

| Icon | Construction idea | Meaning |
|---|---|---|
| Open Node | broken ring + two tracks | public capability interface / exchange |
| Capability Flow | parallel line + sparse arrow tick | transferable capability |
| Route / Switch | forked parallel line | choice / authorization / routing |
| Consent | open hand/check inside open bracket | active user consent |
| Ambient | low-wave line under node | low-risk environmental service |
| Human Override | human silhouette + manual lever bar | human control / intervention |
| Evidence | stacked document lines + source dot | evidence/source record |
| Review | open eye/check frame | public-value review |
| Archive | open box + milepost tick | retirement / memory archive |
| Version | milepost plate `V##` | annual city version |
| Complaint / Appeal | speech bubble + return arrow | contestability / appeal |
| Privacy | open shield + minimal keyhole | privacy boundary, not surveillance |

## 3. Avoid

- robot head;
- brain network;
- microchip;
- infinity loop;
- magic sparkle as AI shorthand;
- face recognition target reticle;
- opaque biometric silhouette.

## 4. Label rule

For public-facing maps and scenario cards, an unfamiliar governance icon must be paired with text on first occurrence. Icon-only use is acceptable only after legend establishment.

## 5. Five-zone indexing

Use alphanumeric zone index blocks (`01`, `02`, `03`, `W1`, `W2`) rather than five decorative mascots.

## 6. Checkpoint

Core icon semantics defined; SVG drafts live in `assets_drafts/` and are explicitly non-final.
