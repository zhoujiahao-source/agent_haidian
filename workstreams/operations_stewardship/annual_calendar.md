# Annual Calendar｜年度运行日历

> Proposed operating rhythm. Exact dates, funding cycles and statutory procedures remain to be set by competent operators.

## Continuous layer — all year

Every month / continuously:
- City Agent + human operators monitor lawful public signals for emerging problems.
- Problem Track and Capability Track remain open.
- Capability Registry is updated for status/version/owner/maintenance changes.
- incidents, complaints, overrides and accessibility issues are triaged.
- bounded trials run only within approved scope.
- maintainers patch, migrate or deprecate capabilities.
- public feedback and objection routes remain available.
- evidence status remains Official / Verified / Derived / Assumed / Unknown.

## Q1 — Diagnose, reopen baselines, set challenge portfolio

Primary outputs:
- previous release lessons translated into unresolved-problem register;
- baseline refresh and data-gap register;
- challenge shortlist with affected groups and non-AI alternatives;
- annual maintenance/retirement review;
- carry-over capabilities rechecked for owner, dependencies and authorization.

Public moment: **Urban Problem Review** — not a product call; publicly explains what still does not work and what evidence is missing.

## Q2 — Design, sandbox, authorize bounded trials

Primary outputs:
- Problem Track briefs opened;
- Capability Track submissions reviewed;
- synthetic/open-data and controlled sandboxes;
- accessibility/distributional co-design;
- professional risk review;
- trial charters defining baseline, risk ceiling, fallback and STOP/MODIFY/CONTINUE/SCALE evidence.

Public moment: **Trial Charter Review** for moderate/high-impact proposals.

## Q3 — Run trials, transfer, revalidate

Primary outputs:
- bounded public trials and community observation;
- cross-area Capability Backbone transfer tests;
- incident/complaint/override evidence;
- maintenance and failover drills;
- interim STOP/MODIFY decisions where signals require action.

Public moment: **Mid-year Learning Review** focused on evidence and failures, not launch counts.

## Q4 — Evidence freeze, independent review, version preparation

Primary outputs:
- trial evidence cutoff date for annual release;
- public-value and distributional review;
- responsible STOPs and retirements prepared;
- unresolved objections listed;
- registry/version history reconciled;
- next-year challenge candidates prepared;
- City Version Release notes drafted and reviewed.

Public moment: **Jing-Zhang City Learning Assembly + Annual City Version Release**.

## Annual release sequence

1. Evidence freeze.
2. Maintainer declarations and unresolved incident check.
3. Professional/independent evidence review.
4. Community/affected-group review of material changes.
5. Public Stewardship decision record.
6. Publish Added / Modified / Scaled / Retired / Responsible STOPs / incidents / metric changes / unresolved problems / next-year challenges.
7. Archive version plus source/audit links.
8. Start next cycle with unresolved items, not a blank slate.

## Cadence anti-patterns

Avoid:
- one annual summit with no year-round rights/maintenance;
- rushing pilots before the conference to create launch announcements;
- postponing STOP decisions until the annual event;
- hiding incidents until release day;
- treating every year as a mandate to increase capability count;
- resetting metrics to make the new version look better.

## Suggested measurable operating-health indicators

These are candidate governance metrics, not official targets:
- share of active capabilities with identified accountable owner and maintainer;
- share with tested rollback/deprecation path;
- time-to-human-review for material incident classes, once competent thresholds are defined;
- percentage of higher-impact trials with affected-group review before public operation;
- percentage of material feedback items with published response/disposition;
- percentage of retired capabilities with completed cleanup + successor/continuity record;
- number/quality of responsible STOPs where continuing would have produced lower public value;
- capability migration/interoperability test pass rate.

Do not optimize these mechanically; use them as audit prompts alongside qualitative evidence.
